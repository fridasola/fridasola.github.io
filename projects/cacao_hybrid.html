🍫 Cas d'Étude : Moteur de Recherche Hybride "CacaoMood"

Domaine : E‑Commerce Wellness · Rôle : Data Architect · Technologies : Azure SQL, Azure OpenAI, T‑SQL

1. Contexte & Problématique

Les clients recherchent à la fois par mots‑clés (origine, pourcentage) et par intentions/mood (ex: "remplacer mon café sans anxiété"). Une recherche textuelle classique échoue souvent pour les intentions sémantiques ; la solution combine Full‑Text + Vectoriel.

2. Architecture technique

  • Pipeline Textuel (Précision) : Index Full‑Text (BM25) pour les correspondances exactes.
  • Pipeline Sémantique (Rappel) : Embeddings 1536‑D + VECTOR_SEARCH (DiskANN) pour similarité cosinus.
  • Fusion Hybride : RRF (Reciprocal Rank Fusion) + Oversampling TOP_N avant post‑filtrage.

3. Modèle de données (T‑SQL)

CREATE TABLE dbo.CacaoProducts
(
    ProductID INT PRIMARY KEY,
    ProductName NVARCHAR(150) NOT NULL,
    OriginCountry NVARCHAR(100) NOT NULL,
    BenefitType NVARCHAR(100) NOT NULL,
    Description NVARCHAR(MAX) NOT NULL,
    CacaoVector VECTOR(1536) NOT NULL
);

4. Requête Hybride (RRF + Oversampling)

Le bloc ci‑dessous montre la stratégie : obtenir TOP_N via VECTOR_SEARCH, fusionner avec FREETEXTTABLE et appliquer RRF pour classer les résultats.

SQL : Requête hybride RRF (exemple) 
DECLARE @userInputText NVARCHAR(1000) = 'remplacer mon café du matin sans stress et avec de la douceur';
DECLARE @userQueryVector VECTOR(1536) = '[0.012, -0.043, ...]'; -- Généré via l'API d'embeddings
DECLARE @rrfK INT = 60;
DECLARE @topN INT = 50;

WITH keyword_search AS (
    SELECT TOP(@topN) p.ProductID,
        RANK() OVER (ORDER BY ftt.[RANK] DESC) AS keyword_rank
    FROM dbo.CacaoProducts p
    INNER JOIN FREETEXTTABLE(dbo.CacaoProducts, Description, @userInputText) AS ftt 
        ON p.ProductID = ftt.[KEY]
),
vector_search AS (
    SELECT TOP(@topN) t.ProductID,
        RANK() OVER (ORDER BY s.distance) AS vector_rank
    FROM VECTOR_SEARCH(
        TABLE = dbo.CacaoProducts AS t,
        COLUMN = CacaoVector,
        SIMILAR_TO = @userQueryVector,
        METRIC = 'cosine',
        TOP_N = @topN
    ) AS s
),
combined AS (
    SELECT TOP(10)
        COALESCE(ks.ProductID, vs.ProductID) AS ProductID,
        COALESCE(1.0 / (@rrfK + ks.keyword_rank), 0.0) +
        COALESCE(1.0 / (@rrfK + vs.vector_rank), 0.0) AS rrf_score
    FROM keyword_search ks
    FULL OUTER JOIN vector_search vs ON ks.ProductID = vs.ProductID
)
SELECT p.ProductName, p.OriginCountry, p.BenefitType, c.rrf_score
FROM combined c
INNER JOIN dbo.CacaoProducts p ON c.ProductID = p.ProductID
WHERE p.BenefitType = 'Énergie'
ORDER BY c.rrf_score DESC;

5. Bonnes pratiques

  • Sur‑échantillonnage (TOP_N élevé) avant post‑filtre pour ne pas perdre pertinence.
  • Métriques cosinus pour embeddings, BM25 pour texte.
  • Mesurer latence et qualité (p@k, mrr) et ajuster rrf_k et topN.
