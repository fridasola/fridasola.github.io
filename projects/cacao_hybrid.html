🍫 Cas d'Étude : Moteur de Recherche Hybride "CacaoMood"

Domaine : E‑Commerce Wellness · Rôle : Data Architect · Technologies : Azure SQL, Azure OpenAI, T‑SQL

1. Contexte & Problématique

Les clients recherchent à la fois par mots‑clés (origine, pourcentage) et par intentions ou états d'esprit (ex: "remplacer mon café sans anxiété"). Une recherche textuelle classique échoue souvent face aux intentions sémantiques. Cette architecture résout le problème en combinant la précision du Full‑Text avec la puissance du Vectoriel.

2. Architecture Technique

  • Pipeline Textuel (Précision) : Index Full‑Text (BM25) pour la correspondance des termes exacts.
  • Pipeline Sémantique (Rappel) : Embeddings 1536‑D + VECTOR_SEARCH (DiskANN) pour évaluer la similarité cosinus.
  • Fusion Hybride : Algorithme RRF (Reciprocal Rank Fusion) combiné avec une stratégie d'oversampling (sur-échantillonnage TOP_N) appliqué en amont du post‑filtrage métier.

3. Modèle de Données (T‑SQL)

Création de la structure de table supportant nativement l'indexation vectorielle des fiches produits :

CREATE TABLE dbo.CacaoProducts
(
    ProductID INT PRIMARY KEY,              -- Clé primaire stricte (Requise pour l'indexation DiskANN)
    ProductName NVARCHAR(150) NOT NULL,     -- ex: 'Élixir Cacao Sacré - Rituel du Matin'
    OriginCountry NVARCHAR(100) NOT NULL,   -- ex: 'Equateur'
    BenefitType NVARCHAR(100) NOT NULL,     -- ex: 'Énergie', 'Relaxation', 'Focus'
    Description NVARCHAR(MAX) NOT NULL,     -- ex: 'Alternative idéale au café. Énergie durable...'
    CacaoVector VECTOR(1536) NOT NULL       -- Embeddings sémantiques de la fiche produit
);

4. Requête Hybride (RRF + Oversampling)

Le bloc ci‑dessous détaille l'implémentation : requêter parallèlement les deux pipelines à hauteur de @topN = 50, puis fusionner les rangs via RRF pour éviter l'exclusion prématurée de produits pertinents lors du filtrage final.

📂 Cliquez pour dérouler le script SQL de la requête hybride 
DECLARE @userInputText NVARCHAR(1000) = 'remplacer mon café du matin sans stress et avec de la douceur';
DECLARE @userQueryVector VECTOR(1536) = '[0.012, -0.043, ...]';
DECLARE @rrfK INT = 60;
DECLARE @topN INT = 50;
DECLARE @targetBenefit NVARCHAR(100) = 'Énergie';

WITH keyword_search AS (
    SELECT TOP(@topN) p.ProductID,
        RANK() OVER (ORDER BY ftt.[RANK] DESC) AS keyword_rank
    FROM dbo.CacaoProducts p
    INNER JOIN FREETEXTTABLE(dbo.CacaoProducts, Description, @userInputText) AS ftt 
        ON p.ProductID = ftt.[KEY]
    WHERE p.BenefitType = @targetBenefit
),
vector_search AS (
    SELECT TOP(@topN) t.ProductID,
        RANK() OVER (ORDER BY s.distance) AS vector_rank
    FROM VECTOR_SEARCH(
        TABLE dbo.CacaoProducts,
        COLUMN CacaoVector,
        SIMILAR_TO @userQueryVector,
        METRIC 'cosine',
        TOP_N @topN
    ) AS s
    INNER JOIN dbo.CacaoProducts p ON s.ProductID = p.ProductID
    WHERE p.BenefitType = @targetBenefit
),
combined AS (
    SELECT TOP(10)
        COALESCE(ks.ProductID, vs.ProductID) AS ProductID,
        COALESCE(1.0 / (@rrfK + ks.keyword_rank), 0.0) +
        COALESCE(1.0 / (@rrfK + vs.vector_rank), 0.0) AS rrf_score
    FROM keyword_search ks
    FULL OUTER JOIN vector_search vs ON ks.ProductID = vs.ProductID
)
SELECT TOP(10) p.ProductName, p.OriginCountry, p.BenefitType, c.rrf_score
FROM combined c
INNER JOIN dbo.CacaoProducts p ON c.ProductID = p.ProductID
ORDER BY c.rrf_score DESC;

5. Bonnes Pratiques Appliquées

  • Sur‑échantillonnage : Maintien d'un TOP_N élevé lors de l'étape de sélection vectorielle pour préserver la pertinence sémantique avant l'exécution du post-filtrage.
  • Harmonisation : Utilisation d'indicateurs de distance cosinus pour le pipeline sémantique et du modèle BM25 pour le traitement textuel.
  • Évaluation continue : Monitorage des indicateurs de qualité (P@K, MRR) pour calibrer dynamiquement la constante de pénalité rrf_k et la profondeur de l'échantillon.
