CacaoMood — Moteur de Recherche Hybride & Fusion RRF

Origine : Approfondissement technique inspiré du cours Microsoft « Concevoir et mettre en œuvre des solutions de recherche intelligente et RAG en SQL » (Microsoft Learn).

Contexte & Problématique

Dans le cadre d'une plateforme e‑commerce spécialisée dans le cacao bien-être (CacaoMood), l'enjeu est de proposer un système de recherche capable de gérer deux types d'intentions utilisateurs radicalement différentes :

  • Les requêtes factuelles épaisses : Recherche précise par mots-clés (nom de produit, pays d'origine, nomenclature exacte).
  • Les requêtes sémantiques ou émotionnelles : Recherche basée sur des états d'esprit ou des bienfaits formulés en langage naturel (ex: "remplacer mon café du matin sans stress").

Architecture Technique & Conceptuelle

Pour maximiser à la fois la précision et le rappel, cette solution déploie une approche hybride combinant deux pipelines distincts au sein de la base de données :

  1. Pipeline Textuel (BM25 / Full‑Text Search) : Indexation classique et efficace pour faire correspondre les termes exacts.
  2. Pipeline Sémantique (Vecteurs & Embeddings) : Recherche vectorielle sémantique s'appuyant sur des modèles d'embeddings (vecteurs de 1536 dimensions) calculant une distance cosinus.
  3. Fusion RRF (Reciprocal Rank Fusion) avec Stratégie d'Oversampling : Algorithme mathématique permettant de fusionner et d'harmoniser deux échelles de scores hétérogènes (des rangs de pertinence textuelle d'un côté et des distances géométriques de l'autre). L'oversampling (récupération d'un plus grand échantillon @topN = 50 en amont) prévient la perte de documents pertinents avant l'application du post-filtrage final.

Schéma T‑SQL de l'infrastructure

Définition de la table intégrant de manière native le support vectoriel pour l'indexation de l'empreinte sémantique :

CREATE TABLE dbo.CacaoProducts
(
    ProductID INT PRIMARY KEY,
    ProductName NVARCHAR(150) NOT NULL,
    OriginCountry NVARCHAR(100) NOT NULL,
    BenefitType NVARCHAR(100) NOT NULL,
    Description NVARCHAR(MAX) NOT NULL,
    CacaoVector VECTOR(1536) NOT NULL
);

Script de la Requête Hybride (RRF + Oversampling)

Voici la structure de la requête Transact-SQL utilisant des expressions de table communes (CTE) pour exécuter parallèlement les deux recherches, fusionner les rangs selon l'algorithme RRF (avec une constante de pénalité de classement k = 60), puis appliquer un post-filtrage par catégorie :

DECLARE @userInputText NVARCHAR(1000) = 'remplacer mon café du matin sans stress et avec de la douceur';
DECLARE @userQueryVector VECTOR(1536) = '[0.012, -0.043, ...]';
DECLARE @rrfK INT = 60; -- Constante de régularisation RRF
DECLARE @topN INT = 50; -- Volume d'oversampling pour le filtrage

WITH keyword_search AS (
    SELECT TOP(@topN) p.ProductID,
        RANK() OVER (ORDER BY ftt.[RANK] DESC) AS keyword_rank
    FROM dbo.CacaoProducts p
    INNER JOIN FREETEXTTABLE(dbo.CacaoProducts, Description, @userInputText) AS ftt 
        ON p.ProductID = ftt.[KEY]
),
vector_search AS (
    SELECT TOP(@topN) t.ProductID,
        RANK() OVER (ORDER BY s.distance) AS vector_rank
    FROM VECTOR_SEARCH(
        TABLE = dbo.CacaoProducts AS t,
        COLUMN = CacaoVector,
        SIMILAR_TO = @userQueryVector,
        METRIC = 'cosine',
        TOP_N = @topN
    ) AS s
),
combined AS (
    SELECT TOP(10)
        COALESCE(ks.ProductID, vs.ProductID) AS ProductID,
        COALESCE(1.0 / (@rrfK + ks.keyword_rank), 0.0) +
        COALESCE(1.0 / (@rrfK + vs.vector_rank), 0.0) AS rrf_score
    FROM keyword_search ks
    FULL OUTER JOIN vector_search vs ON ks.ProductID = vs.ProductID
)
SELECT p.ProductName, p.OriginCountry, p.BenefitType, c.rrf_score
FROM combined c
INNER JOIN dbo.CacaoProducts p ON c.ProductID = p.ProductID
WHERE p.BenefitType = 'Énergie' -- Post-filtrage métier
ORDER BY c.rrf_score DESC;
