Investigation Réseau & Durcissement — yummyrecipesforme

Origine : Activité réalisée dans le cadre de la certification Google en cybersécurité.

Section 1 : Protocole réseau identifié (Étape 3)

Deux protocoles de la couche application ont été observés dans les journaux et en sandbox :

  • HTTP — pages web non chiffrées de yummyrecipesforme.com et du domaine malveillant greatrecipesforme.com (port 80).
  • DNS — résolution de noms menant aux adresses IP des serveurs (requêtes/réponses).

Section 2 : Documentation de l'incident (Étape 4)

Résumé : Le serveur hébergeant yummyrecipesforme.com a été compromis via une attaque par force brute exploitant un mot de passe administratif par défaut. L'attaquant a accédé au panneau d'administration, injecté un script JavaScript malveillant et changé le mot de passe administrateur.

Impact et comportement : Le script invitait les visiteurs à télécharger un exécutable déguisé. Après exécution, le malware modifiait la résolution DNS locale ou redirigeait les requêtes HTTP vers greatrecipesforme.com, provoquant ralentissements et redirections malveillantes.

Sources et preuves :

  • Signalements clients (emails au support).
  • Analyses en sandbox reproduisant la redirection après exécution du binaire malveillant.
  • Journaux tcpdump montrant séquences HTTP et DNS avant et après le téléchargement.
  • Examen du code source confirmant l'injection JavaScript dans l'administration.

Section 3 : Recommandations correctives (Étape 5)

Mesure recommandée : Imposer l'Authentification à Deux Facteurs (2FA) et forcer le changement des mots de passe par défaut.

Pourquoi : Le 2FA empêche l'accès même si le mot de passe est compromis par force brute. Exiger la suppression/modification des identifiants par défaut élimine la vulnérabilité initiale exploitée.

Actions complémentaires suggérées

  1. Forcer la rotation de tous les mots de passe administratifs et désactiver les comptes inactifs.
  2. Activer les protections anti‑brute force (rate limiting, verrouillage, captcha, logs d'IP).
  3. Scanner et nettoyer le code source, restaurer depuis une sauvegarde fiable si nécessaire.
  4. Mettre en place une surveillance SIEM et alertes sur modifications de code et téléchargements suspects.
  5. Forcer l'usage de HTTPS/TLS côté client et serveur (Let's Encrypt + HSTS) pour protéger les utilisateurs contre le MitM.
